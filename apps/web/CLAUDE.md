## Web app (`web`)

Next.js 16 App Router app. Repo-wide commands and layout are in the root `CLAUDE.md`.

### Commands (run in `apps/web`, or prefix with `pnpm --filter web`)

```bash
pnpm dev           # next dev on http://localhost:3000
pnpm build
pnpm lint          # eslint-config-next (core-web-vitals + typescript)
pnpm check-types   # next typegen && tsc --noEmit
```

### Notes

- Source lives in `src/`; alias `@/*` → `src/*`. Routes in `src/app/`.
- `next.config.ts` enables `cacheComponents` and `partialPrefetching` — check the bundled docs in `node_modules/next/dist/docs/` for how these change data fetching/caching before writing server code.
- Route prop types (`LayoutProps<"/">`, `PageProps`) are global helpers generated by `next typegen`; run `check-types` (or `dev`) after adding routes so they exist.
- Tailwind v4, CSS-first: no `tailwind.config`; theme tokens are CSS variables in `src/app/globals.css` (`@theme inline`). Dark mode is class-based (`.dark` ancestor).
- shadcn/ui uses the `base-nova` style built on `@base-ui/react`, not Radix — component APIs differ from Radix-based shadcn. Add components with `pnpm dlx shadcn@latest add <name>`; they land in `src/components/ui/`.
- `cn` comes from the `cn` npm package (re-exported from `src/lib/utils.ts`), not `clsx` + `tailwind-merge`.
- Icons: `lucide-react`.
- Screens read data only through `src/data/<area>.ts` (one async function per screen). Until a procedure exists these return typed fixtures from `src/mocks/` (keyed by organization code; `src/mocks/tenants.ts` only holds mock exception owners). Settings and licensed modules are real (`getSession().organization`); module data functions call `requireModule(module, permission?)`. Swap the function body for the tRPC call in the PR that ships the procedure. See `docs/build-plan.md` → "UI track".
- Request-time reads go inside `<Suspense>`. Anything that reads the clock calls `await connection()` first; `cookies()` alone does not make a subtree request-time under partial prefetching.
- `/design` previews the tokens. Grids use `DataGrid` (`src/components/data-grid.tsx`, TanStack Table v9); money uses `MoneyText` and never converts to `number`.
- Auth: Better Auth at `/api/auth/[...all]`, created lazily in `src/server/auth.ts`. `src/data/session.ts` reads the session and the user's one organization, and redirects to `/sign-in` without them. Sign-in sends the organization code header with email or a qualified username; sign-out uses `authClient` from `src/lib/auth-client.ts`. There is no organization switching (requirements §1). `getSession()` also returns `access` (role and permissions); `getApi()` gives an in-process tRPC caller acting as the user. Data functions call `requirePermission(p)` (not found without it) and nav items carry a `permission`; hiding is wayfinding only, procedures enforce. `/settings/team` grants and revokes extra permissions via a server action (`refresh()` after). Permission and role labels are in `src/lib/permission-labels.ts`. `/settings/areas` shows and edits the hierarchy and routes (`src/data/hierarchy.ts`); the team sheet's Coverage section sets scope restrictions. `access.scope` limits what data functions return (mock accounts match by zone name and route code until the accounts procedure filters by ids). `authClient` and the in-process caller name themselves as `web` for the audit log. The exception queue (`src/data/exceptions.ts`) shows real kernel exceptions with take, assign, retry and resolve actions (`/exceptions` server actions), plus demo rows from `src/mocks/exceptions.ts` (marked `demo`, no actions) for module queues that have not shipped. `/settings/audit` (needs `audit:read`) lists entries with filters, paging and the chain check; action names are in `src/lib/audit-labels.ts`. `/settings/organization` edits time zone and language (`src/data/config.ts`, a new configuration version per save, with its history) for members with `settings:manage`, and shows them read-only otherwise; language labels are in `src/lib/languages.ts`. Never import a non-component value from a `"use client"` file into a server component: it arrives as a client reference. The header bell (`src/components/shell/notification-bell.tsx`, `src/data/notifications.ts`) shows in-app notifications, polls once a minute, and marks them read when opened. `src/lib/tree.ts` flattens parent-linked lists for display.
