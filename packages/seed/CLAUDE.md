# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## `@flowless/seed`

Dev data for local testing: `pnpm db:seed` (root) runs `src/seed-dev.ts`. Idempotent; refuses `NODE_ENV=production`. Needs `DATABASE_AUTH_URL` and `DATABASE_URL` from the root `.env`.

- Identities (organizations, owners, staff) come from `seedDevIdentities` in `@flowless/auth/dev-seed`, the only code allowed to touch the `auth` schema.
- Everything else is written through the real API: it signs in as each owner with the organization code, resolves the caller with `getCaller`, and uses `createCaller`, so seeds obey permissions, validation and RLS. Settings come from the `organization.created` event (the seed drains the outbox, as the worker would; initial settings are in `DEV_ORGANIZATIONS` in `@flowless/auth/dev-seed`). The one exception is licences, set with `setEntitlements` because only Flowless licenses (MAJISAFI has the foundation plus communications, collections, work orders, GIS and reporting; KILIMA the foundation only).
- Area and route names match the web mocks (`apps/web/src/mocks/accounts.ts`). Add new dev data here as each module's procedures land; nothing imports this package.
- `src/seed-network.ts` (Phase 2): for MAJISAFI a small Kahawa West network (reservoir, valves, inlet meter in a chamber, junctions, hydrant, pipes, four connections, DMA-KW1's boundary; restores DMA-KW1 and its parents if they were archived) and seven jobs (assigned, unassigned, overdue, one submitted for review). Staff `juma` (technician) and `njeri` (supervisor) come from `@flowless/auth/dev-seed`. Each part is skipped when it already exists.
- Ordering: licensing publishes `entitlements.changed`, which is what gives Tariffs its default categories, charge items and invoice types, so `seed-dev.ts` drains the outbox right after `setEntitlements` and again at the end of each organization (approval decisions and status events settle). A single `pnpm db:seed` on an empty database is enough; a re-run changes nothing.
- `src/seed-accounts.ts` (Phase 3, MAJISAFI only, after the network): written as the owner, with the clerk `baraka` recording surveys so the owner can approve (signed in by username through the same helper as the owner). Keys for "already there" are tariff names, customer names (and the shared accounts list), application addresses, the settings' version 0. Contents:
  - Tariffs: five (Domestic block tariff = the requirements section 6 reference bands, first version dated four months back and a second, first band 95.00, scheduled for the next period start; commercial and institution uniform; bulk reseller uniform; kiosk flat rate; farming flat rate by pipe size), the six categories assigned to them with standing charge 150.00 and meter rent where they apply, amounts for ten catalog items (one scheduled rise of the connection fee), the new-connection invoice type on a 50% minimum deposit, the usage type with a late-fee rule and disconnect after 30 days. Membership classes `member` and `non_member`, and `accounts.data_quality` raising exceptions for `account_no_phone` and `zone_equals_route`.
  - 27 accounts in Kahawa West and Githurai 45: 17 ACTIVE+CONNECTED (including a water users group parent with children `A`, `B`, `C` and a membership class), 1 ACTIVE+DISCONNECTED for non-payment, 3 DORMANT (one of them from the succession), 1 TERMINATED, 3 NEW (one aged 30 days), 2 PENDING_PAYMENT (one aged 30 days, one from the converted application); service points with GPS near the area centres, four linked by `gisConnectionId` to the GIS connections `KW-0001` to `KW-0004`. The GIS side (`service_connection.service_point_id`) is set only when a connection is created and the seed's connections predate the service points, so it stays null: GIS has no procedure to set it later. Data-quality gaps: no phone, a placeholder phone, no coordinates, one national id on two customers, a route keyed as the zone (R-02 on a Kahawa West point), no category. Joseph Karanja's account is succeeded by Margaret Karanja (own number), Hassan Abdi's account changes name to Abdi Hardware Limited, and James Mutua has a relocation to Githurai 45 in progress (surveyed).
  - 6 applications: an enquiry with a survey job in Work Orders (assigned to `juma`), an enquiry whose survey awaits approval, and applications at `application`, `invoice`, `ready` and `converted`.
  - The real sweeps then run (`sweepStaleAccounts`, `sweepDataQuality`): 2 `STALE_ACTIVATION` and 3 `DATA_QUALITY` exceptions on a fresh seed.
  - Dev-only backdating goes through `DATABASE_ADMIN_URL` (the owner role; the same way the integration tests age rows): the two stale accounts, and the opening holder of the change-of-name account (a holder who took over today cannot be replaced today). Without that variable these steps are skipped with a warning.
