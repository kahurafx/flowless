# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## `@flowless/api`

Reference /trpc skill.

The tRPC layer: every procedure in Flowless lives here. Phase 0 scaffold: `trpc.ts` (superjson, `tenantProcedure`), `root.ts` (`health`, `organization.settings`), `http.ts` (`createTrpcHandler({ endpoint, getDb, getSession })`). `Session` is the narrow slice of `Caller` (from `@flowless/auth`: Better Auth session plus the current membership) the API uses; `tenantProcedure` takes `session.activeOrganizationId` (UNAUTHORIZED without a session, FORBIDDEN without an active organization or when `session.member` is missing or elsewhere) and exposes `ctx.organizationId`, `ctx.role`, `ctx.permissions` (role defaults plus `kernel.member_permission` grants, K-03) and `ctx.tx`. Guard actions with `permittedProcedure("<resource>:<action>")`; the catalogue and default roles are in `@flowless/shared-types` permissions. `ctx.scope()` (lazy, `kernel/scope.ts`) is the member's scope restriction, `all` or `limited` area and route ids expanded to everything below. `kernel/access.ts`: `access.me` (role, permissions, scope), `access.grants`, `access.grant`, `access.revoke`, `access.scopes`, `access.setScope` (a limited manager gives only scope inside their own, never unrestricted). `kernel/hierarchy.ts` (K-02): `hierarchy.areas`/`routes` for everyone; create, update, archive and restore need `settings:manage`. Events (K-09): define with `defineEvent(type, zodSchema, version)` in the module's `events.ts`, publish with `ctx.publish(event, payload, { id? })` in the change's transaction, consume with `defineConsumer({ name, module, event, handle })` registered in `kernel/consumers.ts`. Consumers run once per event (receipts) inside the event's tenant and must be idempotent; on `replay: true` skip effects outside the database. `dispatchOutbox`, `drainOutbox` (tests, seeds) and `replayEvents` are in `kernel/events.ts`. Jobs (NF-12): `defineJob({ type, module, label, schema, run })` registered in `kernel/job-registry.ts`, queued with `ctx.enqueue(job, payload, { idempotencyKey?, runAt? })`; `run` writes through `ctx.withTenant` per unit of work, calls `ctx.heartbeat()` on long runs, and must be safe to run again. Exceptions (X-02, NF-24): raise with `raiseException(tx, organizationId, { type, source, title, subject, areaId?, routeId?, ownerUserId?, dedupeKey? })` from `kernel/exception-store.ts`; `exceptions.list` needs `exceptions:read`, `assign`/`start`/`resolve`/`reopen`/`retry` need `exceptions:resolve`, and scope applies. Every change writes `ctx.audit({ action, subjectType, subjectId, before, after })` (K-06) in the same transaction; skip it when nothing changed. `Context.source` (web, mobile, api, import, system) comes from the `x-flowless-client` header in `http.ts`, or is set by in-process callers. `audit.list` and `audit.verify` need `audit:read`. `setEntitlements` audits as a system action. `moduleProcedure(module, ...permissions)` is the builder for module routers: licence first (NOT_FOUND when unlicensed), then permissions; `ctx.entitlements()` is lazy. `entitlements.list` for everyone; `setEntitlements(db, organizationId, modules)` (exported, server-side only, never a procedure) is how Flowless licenses an organization. Keep `kernel/entitlement-store.ts` free of `../trpc` imports, since `trpc.ts` imports it. Configuration (K-10, NF-32): define with `defineSetting({ key, module, label, description, schema, default })` (`kernel/config-store.ts`; the schema must keep reading every stored version, so add fields with `.default()`), register in `kernel/config-registry.ts`, read with `ctx.config(setting, at?)` or `readSetting(tx, setting, at)`. `config.list`/`history`/`set` need `settings:manage`; `set` takes `expectedVersion` (CONFLICT when stale) and an optional future `effectiveFrom`, and writes nothing when the value is unchanged. `organization.settings` returns currency plus `kernel.regional` (time zone, language). Keep `kernel/config-store.ts` free of `../trpc` imports. Map Postgres errors with `kernel/pg-errors.ts`. Tests share `src/test-support.ts` (`addMember`, `sessionOf`, `callerFor`). Apps read error messages with `clientErrorMessage`, never by importing `@trpc/server`. Target layout and boundary rules are in `docs/build-plan.md` → "Code layout". Shared package conventions are in the root `CLAUDE.md`.

- Layout: `src/trpc.ts` (context and base procedures), `src/root.ts` (`appRouter`, `export type AppRouter`), `src/kernel/*`, `src/modules/<module>/{router,service,events,index}.ts`.
- Module routers build procedures only from `moduleProcedure(module)`. That runs `withTenant` (RLS) and the entitlement check. Never use the raw DB client.
- A module touches only its own `@flowless/db` schema. It reaches other modules through their `index.ts` or through events.
- Long-running work is enqueued for `apps/worker`; procedures never run billing, imports or reconciliation inline.
- Server-only package (Node). `apps/web` imports it at runtime. `apps/mobile` may only `import type { AppRouter }`.
- No build step: consumers import `src/index.ts` directly via `exports`. Scripts: `pnpm lint`, `pnpm check-types` (or `pnpm turbo run check-types --filter=@flowless/api`).
