# GIS module (`packages/api/src/modules/gis`)

Phase 2 W3, ported from Majimap. Moved unchanged out of `packages/api/CLAUDE.md`.

`createGisRouter(work)` mounted at `gis` (nodes, structures, pipes, connections, dmas, tiers, subnetworks, attachmentRules, trace, logs, reconcile, reports). Procedures from `gisProcedures(work)` (`procedures.ts`): `read` (`gis:read`: the network, history, traces, logs, branch list and preview), `edit` (`gis:edit`), `remove` (`gis:delete`: delete, restore, deleteImpact), `post` (`gis:post`: post, discard) and `configure` (`gis:configure`: tiers, subnetworks, attachment rules); write procedures seed the organization's attachment rules on first use. The versioning engine (`versioning/`) is Majimap's as it is: every edit supersedes a version (compare-and-set on `is_head`), a branch's first edit is built from the client's base version of main, `merge.ts` is the pure field-level three-way merge, `post` applies a branch in a savepoint (all or nothing; integrity violations come back as `status: "invalid"`, conflicts as `"conflicts"`), deletes are tombstones, `restore` undoes one on main. A DMA's map data is keyed by its kernel area (`keyOf`/`normalize` make `id` the area id; the name is the area's, read with `areasById` from `kernel/areas.ts`, which also checks level "dma"). Every write checks the branch first (`versioning/branch-write.ts`): main needs `gis:post`; other branches go to `work.checkBranchWrite` (`wo-` is Work Orders' guard, `fld-<userId>` GIS's personal-branch guard, `field-` reserved and refused). Posting a job's branch needs the job completed or `override`, and a cancelled job's branch can only be discarded (from the `wo-` annotator's status). Logs (`logs.ts`) are always kept; the asset edit they imply happens only where the caller may write, otherwise the outcome is `stale`; Work Orders links a log only if it was recorded on the job's branch (`EvidenceRef.branch`). Wire format: locations are `{ lat, lng }` (the database's and `@flowless/network`'s), dates are `Date`; the resolvers convert to `GeoPoint` for the ports. GIS holds no customers: `service_connection.service_point_id` is optional, and a connection going live publishes `gis.connection_posted`. Outbox events (`events.ts`): `gis.condition_changed` (main only), `gis.connection_posted`, `gis.branch_submitted` / `.branch_ready_for_reconcile` / `.branch_cancelled` (the job effects); the consumer `gis.seed_attachment_rules` seeds `structure_attachment_rule` from `STRUCTURE_ATTACHMENT_RULES` on `entitlements.changed` (idempotent; `attachmentRules.set` never empties them, so "no rules" means "never seeded"). Post, discard, restore and configuration changes are audited (`gis.*`). Reports `gis.recent_findings` and `gis.condition_trend` are `defineReport`s; `summary` and `alerts` are procedures. `index.ts` exports `register(work)` (the 11 GIS kinds, all tier basic; asset and evidence resolvers; effects; the `fld-` guard; the reserved `field-`), the `gis_asset` file subject (read `gis:read`, add and remove `gis:edit`, manage `gis:post`; required photos are checked at post) and the reports. Tests: `modules/gis/test/test-support.ts` (`setupTestEnv`: four organizations, the roles, `photo`, `events`, `dmaArea`); `job-branches.test.ts` covers jobs end to end on the real GIS.
